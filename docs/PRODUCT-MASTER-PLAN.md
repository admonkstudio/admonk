# Product Master Plan — Unified Company Operating Environment

**Date:** 2026-09-29  
**Status:** LOCKED — OWNER APPROVED / FOUNDATION-M3 COMPLETE  
**Foundation:** M1 locked; M2 locked with M3 reinterpretation where noted; M3 reconciled 2026-09-29.  
**Working environment name:** SOLO — temporary, not final brand.  
**Intelligent operator:** SIA.

---

# 1. Vision

Build one coherent operating environment that can serve a one-person business, a team, a department or a large enterprise without forcing the customer to assemble and maintain separate internal applications for every function.

Core formulation:

> **One company. One operating environment. Every role gets the right lens. SIA is the company brain.**

The environment models:
- people;
- departments/teams;
- roles;
- responsibilities;
- processes;
- systems;
- data;
- documents;
- metrics;
- goals;
- meetings;
- approvals;
- artifacts;
- automations;
- relationships;
- actions.

SIA operates over that model under explicit authority.

---

# 2. Product model

## One company tenant

A company has one primary operating environment.

New users join the existing company model rather than installing a new departmental product.

## Role lenses

Each user receives an experience assembled from:
- role archetype;
- actual responsibilities;
- organizational scope;
- permissions;
- connected systems;
- company processes;
- selected capabilities;
- personal/team context.

## Domain capability packs

Marketing, Recruiting, Support, HR, Operations, Finance and future domains provide:
- semantics;
- responsibilities;
- metrics;
- process templates;
- components;
- artifacts;
- diagnostics;
- connectors/actions;
- specialist profiles.

They are not automatically separate software products.

---

# 3. SIA

SIA is the single visible intelligent operator/company brain.

SIA owns:
- user conversation/voice interaction;
- intent;
- company-level plan;
- routing;
- task decomposition;
- context selection;
- specialist/workflow selection;
- synthesis;
- recommendations;
- progress;
- user-facing explanation;
- escalation;
- result verification.

SIA does not own authoritative source data merely because it reasons over it.

Principle:

> **No artificial functional ceiling; bounded authority always.**

---

# 4. Execution architecture

For every request, SIA chooses the appropriate execution mode.

## DIRECT
SIA handles simple reasoning/action.

## WORKFLOW
Deterministic durable workflow performs known steps.

## SPECIALIST
One temporary specialist run handles narrow expert work.

## TEAM
Multiple independent specialists work in parallel.

## HYBRID
SIA + specialists + deterministic workflow + humans.

Multi-agent execution must earn its cost.

---

# 5. Specialist architecture

Specialists are reusable profiles, not permanent employees/processes.

A Specialist Profile defines:
- purpose;
- eligible work;
- tools;
- context needs;
- policy;
- output schema;
- quality rubric;
- budget;
- model preference;
- escalation.

A Specialist Run is temporary and scoped to:
- task;
- tenant;
- authority;
- context;
- budget;
- deadline.

Resulting work persists as artifacts/evidence.

# 8. Three onboarding modes

## Adapt to Us
Learn and preserve a mature custom process.

## Help Us Build

## Start with Standard
Activate a curated default role/process model quickly.

# 9. Process intelligence

Maintain three views where useful:

**Reference** — common/best-known pattern.  
**Configured** — declared company process.  
**Observed** — actual evidence of how work occurs.

SIA can identify:
- drift;
- bottlenecks;
- missing ownership;
- bypassed approvals;
- shadow work;
- training gaps;
- automation opportunities.

# 10. Interactive experience

SIA is AI-first, not chat-only.

Interaction levels:

1. conversation/voice;
2. inline interactive components;
3. context drawer/panel;
4. dynamic workspace;

SIA composes approved components.

# 14. Human + digital workforce

Responsibilities may be fulfilled by:

- human;
- automation;
- SIA Specialist;
- hybrid.

SIA may detect:
- missing capacity;
- overload;
- repeated manual work;
- unowned responsibility.

It can recommend:
- remove/redesign step;
- connect system;
- train/reassign;
- automate;
- hire;
- add digital specialist.

Digital specialists progress through:

**Draft → Simulation → Shadow → Supervised → Bounded Autonomous**

No self-promotion.

# 15. Temporary department continuity

If a function loses human capacity, authorized owners may allow SIA to provide temporary digital coverage.

SIA:
- maps critical responsibilities;
- assigns safe work;
- keeps human-required decisions with authorized people;
- reports operations;
- preserves full evidence;
- supports later transfer back to human staff.

# 16. Integrations and authority

Connect providers once where practical.

Separate:
- read access;
- action authority.

All consequential actions flow through:
- user/delegator authority;
- capability;
- tenant/company policy;
- provider scope;
- context;
- action class;
- approval;
- runtime budget.

The model never grants itself authority.

- AI agents;
- knowledge graphs;
- workflow builders;
- process discovery;
- interactive artifacts;

Current differentiation hypothesis:

> **A role-first operating environment that already understands how work commonly works, learns how this company actually works, and lets one SIA coordinate humans, deterministic software and specialist AI through one coherent interactive experience.**

---

# 23. Product principles

1. **Model the work first; assign the worker second.**
2. **One brain. Many specialist capabilities.**
3. **Use AI where judgment helps; use deterministic software where certainty helps.**
4. **Prebuild the interaction vocabulary; let SIA compose it.**
5. **Preserve authoritative truth with its owner.**
6. **Immediate visible feedback, even when work continues.**
7. **No arbitrary functional ceiling; bounded authority always.**
8. **Progressive complexity: solo simple, enterprise governed.**
9. **Defaults accelerate; customers may adapt.**
10. **Measure whether recommended change actually improved work.**

---

# 24. Current non-goals

Do not:
- create separate apps merely because a department exists;
- create one agent per role;
- expose an agent marketplace as the main UX;
- generate arbitrary production UI at runtime;
- centralize every source database;
- replace governance with model reasoning;
- claim work succeeded without authoritative receipt;
- force every customer into the reference process;
- optimize for component count or agent count.

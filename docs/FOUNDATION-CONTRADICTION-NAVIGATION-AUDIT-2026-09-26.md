## Contradictions found and resolved during FOUNDATION-M1

1. **Exception semantics**
   - Old rule: “No permanent exceptions.”
   - Current rule: S030/PB07 Temporary or explicitly approved Permanent exceptions; Temporary requires expiry/review, Permanent remains reviewable.

2. **Prototype artifact burden**
   - Old rule: four separate files before implementation.
   - Current rule: require the information; a simple Prototype may use one Prototype Definition and split artifacts progressively.

3. **Consequential approval**
   - Old wording could imply separate approval + confirmation every time.
   - Current rule: approval is action-bound; one valid approval may authorize the exact action without redundant confirmation.

4. **Lifecycle vs risk**
   - Old model: Prototype / Production / High-risk as one governance scale.
   - Current model: Prototype / Production lifecycle + independent risk overlays. High remains release-risk/finding severity, not lifecycle.

5. **Design Foundation maturity**
   - Old status: structural/research only.
   - Current status: Level-1 rules approved for accessibility, component promotion, semantic tokens and design↔code authority; fixed universal tokens/components remain intentionally unpopulated.

6. **Research/tool status drift**
   - Old status still showed Standards/Playbooks/validations and T024–T028 as unfinished.
   - Current status records R001–R016, T017–T028, S001–S030 and PB01–PB07 complete, with BriefFlow and Marketing Hub revalidation passed.

7. **Version truth**
   - The working Product Supervisor contains material post-v1.1.0 governance changes.
   - It is now correctly labeled **Unreleased FOUNDATION-M1 candidate**, while v1.1.0 remains the latest stable release until final lock.

# PB07 — Foundation Exception & Tool Decision

**Trigger:** Material Standard deviation; temporary/permanent exception; significant new tool/service/platform; tool replacement; overlapping capability.
**Principle:** Both exceptions and tools deliberately accept additional risk or complexity.

## Path A — Foundation exception
1. State the exact rule.
2. Explain why deviation is needed.
3. State accepted price: security/privacy/cost/reliability/manual work/lock-in/maintenance/accessibility/compatibility/AI authority.
4. Use the smallest useful compensating control.
5. Decide: **Approved / Rejected / Needs different solution**.
6. Temporary exception: owner + expiry/review condition. Permanent exception: explicit approval and ongoing reviewability; no artificial expiry required.

## Path B — New tool decision
1. Start with missing capability, not product name.
2. Evidence ladder: **existing/native → lightweight addition → dedicated/heavier system**.
3. Compare total cost: money, implementation, maintenance, training, privacy/security, integrations, lock-in, operations, removal/migration.
4. Compare measurable benefit.
5. Status: **Adopt / Adopt conditionally / Pilot / Defer / Reject**.
6. Explicitly justify overlapping capability.
7. Define exit/revisit trigger.

## Required record
**Decision → Capability/rule → Current approach → Alternatives → Evidence → Benefit → Accepted cost/risk → Status → Owner → Trigger/expiry if applicable**

# PB01 — Product Definition & Scope

**Trigger:** New product, major capability or material expansion.
**Outcome:** A fresh person/AI can explain who needs it, the problem, evidence, desired outcome, smallest coherent version, boundary and learning plan.

## Flow
1. Define target user, problem/job, current workaround and why it matters.
2. Attach minimum useful evidence; label weak evidence honestly.
3. Define observable success before prescribing implementation.
4. Define the smallest coherent solution that can test real value.
5. Record **Now / Later / Not this version**.
6. Flag only material risks/expensive boundaries.
7. Decide: **Proceed / Test first / Stop or defer**.

## Required record
**User → Problem → Evidence → Desired outcome → Smallest coherent version → Now/Later/Not-now → Material risks → Decision**

## Completion
A fresh person/AI can answer: **Why are we building this, what are we building now, what are we deliberately not building, and how will we know whether it worked?**

# Tool / Technology Evaluation Framework

**Purpose:** Decide whether a tool, technology or connector earns its complexity footprint.

## Scorecard questions

| Criterion | Question |
|---|---|
| User value | What real product/team problem does it solve? |
| Evidence | What reliable signal does it produce? |
| Feedback loop | Which decision/action changes because of that signal? |
| Integration | Can it fit the current workflow without duplication? |
| Complexity | What permanent operational/support burden does it add? |
| Cost | What is the initial and future cost? |
| Portability | Can data/workflows be exported or migrated? |
| Security | What access/sensitive data does it require? |
| Maturity | Is it dependable enough for the required project stage? |
| Reversibility | Can it be replaced without major redesign? |
| Ownership | Who maintains it and responds to failures? |

A tool that creates data but does not influence a decision/action is presumptively unnecessary.

## Decision outcomes

### Adopt now
Required for the current Admonk baseline.

### Adopt conditionally
Required only at a certain risk, stage, product type or architecture.

### Pilot
Promising, but needs validation in a real controlled project.

### Defer
Potentially useful, but current value does not justify adoption.

### Reject
Insufficient value, duplicate capability, unacceptable risk/cost, or unnecessary complexity.

## Decision rule

Do not adopt a tool because it is "industry standard."

Adoption requires:
**validated problem + useful evidence loop + acceptable complexity/cost/risk + clear ownership + viable exit path.**

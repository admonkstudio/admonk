# Admonk Standards

**Status:** Structure created; standards should be authored only from approved doctrine plus authoritative requirements.

Standards answer:

> **What must be true, and what evidence proves it?**

Potential areas may include:
- UX;
- code simplicity;
- repository/knowledge architecture;
- accessibility;
- security;
- AI/agent controls;
- release quality.

A standard must be sufficiently testable to support an evidence-based review.

Do not use standards to force:
- a universal dashboard layout;
- a fixed visual style;
- one business model;
- one feature hierarchy;
- one technology stack;
- other product-specific strategic answers.
